# Feature 021 prompt — Incremental freshness status

## Authoritative request

Optimize the F020 status/freshness bottleneck incrementally or sublinearly in prepared block count while preserving exact
source change detection, explicit integrity truth, local-first behavior and reproducible evidence. Complete physical and
semantic representation verification must remain available as an explicit operation rather than being silently removed.

## Frozen scope

- Default status hashes the authoritative source exactly and reads no representation block projections or block objects.
- Every result declares `NONE`, `HEAD` or `FULL` integrity coverage.
- Full verification remains an explicit service/CLI mode; identifier-only MCP cannot request it.
- The F020 10,000/100,000-block corpora and committed status baselines are retained and measured separately.
- Storage-amplification reduction, PDF model provisioning, real-world corpus work and semantic question evaluation remain
  separate sequential Features 022–025.

## Completion boundary

Complete the full Spec Kit lifecycle, tests-first implementation, decision-bearing offline benchmark, independent result
validation, full local gates, one private pull request and green Linux/macOS/Windows CI before starting Feature 022.
