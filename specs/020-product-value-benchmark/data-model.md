# Data Model: Product Value Benchmark

All records are strict, closed and canonically identity-bearing. They are internal benchmark evidence, not new public
OpenARDP interchange contracts.

## BenchmarkProtocol

- `schema_version`: internal evidence schema version
- `protocol_version`: measurement protocol version
- `profiles`: smoke, reference, scale and full compositions
- `warmups`, `repetitions`, `bootstrap_resamples`, `confidence_level`
- `metrics`: closed metric/unit registry
- `resource_limits`: source, block, time, workspace and result bounds
- `privacy_policy`: prohibited output classes
- `protocol_id`: canonical SHA-256 over the identity projection

## CorpusSpec and CorpusManifest

`CorpusSpec` fixes generator version, seed, per-profile block counts, paragraph grammar, query target ordinals, rich
fixture identities and edit recipes. `CorpusManifest` is produced from generated bytes and records only relative logical
names, hashes, byte lengths, block counts and redistribution facts.

Validation rules:

- generated source bytes must match the frozen grammar and exact counts;
- all query targets are unique and within their profile;
- source sizes remain within the product and protocol bounds;
- rich fixtures must match committed identities before use.

## BenchmarkJudgment

- `workload_id`, `profile`, `query_id`
- expected logical document and unique fact identifier
- expected evidence/source locator class
- context budgets and expected fact coverage
- edit predecessor/successor identifiers where applicable

Task text and source bodies are runtime inputs derived from IDs and are not copied to evidence outputs.

## EnvironmentClass

- OS family and major version class
- architecture
- Python major/minor
- logical CPU count bucket
- physical-memory bucket when available
- timer and peak-RSS measurement methods
- `reference_timing` flag
- canonical `environment_id`

It excludes hostname, username, serial numbers, exact home paths and environment variables.

## BenchmarkObservation

- all normative IDs: protocol, corpus, policy, environment
- `profile`, `workload_id`, `treatment`, `phase`, `metric`, `unit`, `repetition`
- `status`: passed, failed, unavailable or rejected
- numeric `value` only for passed observations
- stable closed `reason_code` only for non-passed observations
- `observation_id`: canonical SHA-256 over all fields except itself

Duplicate observation keys or IDs, negative/non-finite values, mismatched units and unknown reasons are invalid.

## MetricSummary

- exact grouping identity
- retained and rejected sample counts
- minimum, maximum, p50, p95, median absolute deviation
- deterministic 95-percent bootstrap interval
- source observation IDs

Only homogeneous passed timing samples are statistically aggregated. Counts, ratios and bytes use explicitly named
deterministic reductions instead of misleading latency statistics.

## WorkloadOutcome

- correctness ratios and stale incident count
- parser invocation facts
- preparation and repeated-task medians
- raw-reparse and native-reuse break-even counts or `not-observed`
- selected/native ratio
- format/profile completeness
- referenced summaries and observations

## ValueDecision

- `decision_version`, `decision_id`
- `outcome`: `WORTHWHILE`, `CONDITIONALLY_WORTHWHILE`, `NOT_DEMONSTRATED`
- protocol/corpus/policy/environment/run identities
- ordered checks with expected, observed, status and evidence IDs
- stable ordered reason codes
- tested claims, limitations and explicit non-claims
- inherited F015 release status and decision identity

### State transition

```text
raw observations
    -> validated complete run
    -> deterministic summaries
    -> frozen-policy checks
    -> one ValueDecision
    -> deterministic report projection
```

Invalid or incomplete raw evidence never transitions to a favorable decision.

## BenchmarkRunManifest

- identities and expected file inventory
- SHA-256 and byte length for every published file
- terminal completion marker

Publication stages all files in a sibling temporary directory and renames the complete directory atomically. Existing
results are accepted only when every expected byte agrees.
